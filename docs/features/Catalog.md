## Overview

Living model catalog and resolve helpers. Callers pass knobs or inject fixtures — no app settings import.

The same `cheapest` / `economy` / `best` intents run on a **role-filtered** pool (`chat` \| `image` \| `video` \| `voice` \| `speech-to-text`). SDK fetch unions language models with image-generation models so those roles are not empty; video, voice, and speech-to-text rows are tagged by slug when they appear. `grok-voice-transcribe*` is speech-to-text, not voice.

## Architecture / Contract

- **Owns**: fetch/cache/list `ModelInfo`; resolve `cheapest` / `economy` / `best` / pin / task hook / bootstrap. `role=` selects the pool
- **Does not own**: billing UI, per-app task names (apps inject `set_task_assignment`)
- **Public API**: `list_models` (`persist_path=`), `save_catalog_snapshot`, `inject_catalog`, `resolve_model` / `resolve_model_selection` (`role=`, `need=`), `normalize_thought_level`, `contract_thought_level`, `contract_model_for_need`, `normalize_intent`, `effort_options` (`model=`), `feature_options` (`model=`), `intent_options`, `BOOTSTRAP_MODEL`, `ModelInfo`, `ModelSelection`

Resolve chain: **pin → need-filter → intent (`cheapest`\|`economy`\|`best`) → task hook → prefer_latest → bootstrap** (`grok-4.7` for chat; image, video, voice, and speech-to-text use that role's default slug when the pool is empty). Speech-to-text empty-pool default is `grok-voice-transcribe-2.0`. Offline with no key/fixture, `list_models` injects `grok-4.7` plus cheaper-band `grok-4.3`.

`normalize_thought_level`: canonical `low`\|`medium`\|`high`\|`xhigh` (4.6 set). `med`/`mid` → `medium`; `x-high`/`extra`/`max` → `xhigh`; empty/unknown → omit knob. `contract_thought_level(level, model)` clamps to what that family accepts (4.6+/multi-agent pass through; 4.5 `xhigh`→`high`; older reasoners also `medium`→`low`; `*-non-reasoning*` omits). `effort_options(model=)` returns that family's list (empty when none). `grok-4.20` is older than `grok-4.5` — do not treat numeric 20 as “4.6 and later”.

`feature_options(model=)`: extra capabilities (tools + media), not role tags. No model / `grok-4.6`+ chat (including `grok-4.7`) → `web_search`, `x_search`, `code_execution`, `file_attachments`, `collections_search`, `image_understanding`, `x_video_understanding`, `mcp` (not `batch` — live Batch rejects 4.6/4.5; the 4.7 model page says Batch API is not supported). `grok-4.3` → `batch`. `grok-imagine-video` (quality) → `video_extend`, `video_edit`, `r2v`. `grok-imagine-video-1.5` → `1080p`, `r2v`. `grok-imagine-video-1.5-lite` → `1080p` only. Unknown / older → `[]`. `resolve_model(..., need=)` / `need=["video_extend", …]` keeps only SKUs that have every requested extra, then runs cheapest / economy / best on that pool. Pin still wins. Empty need-filtered pool bootstraps a kit-known slug that has the extras (quality for extend; `grok-4.3` for batch).

`intent_options()`: `cheapest`, `economy`, `best`. Overlap is allowed when the lineup is thin. `economy` is the cheaper-than-flagship rung, not a performance-per-dollar optimum.

## Behavior (stable)

- SDK fetch with fallback to empty/offline catalog when allowed. `fetch_models_from_sdk` passes `timeout=` to `xai_sdk.Client` (XK-TO-1). A client passes its resolved timeout. A direct call with no timeout uses 180.0 and does not read `XAI_SDK_TIMEOUT_SECONDS`. `list_models` checks `sdk_timeout` before the fetch: an invalid value raises `ValueError` and writes nothing. A deadline (`XaiTimeoutError` or gRPC `DEADLINE_EXCEEDED`) uses the same persist, fixture, and bootstrap fallbacks as any other SDK failure. That fallback is cached for `CATALOG_TIMEOUT_RETRY_SECONDS` (60) instead of the full TTL, then the next call fetches again. If every SDK list fails and any error is a deadline, that deadline is the one raised. Other SDK failures still cache the bootstrap pair for the TTL.
- Fetch unions `list_language_models` + `list_image_generation_models` (best-effort: one list failing does not wipe the others). No video, voice, or speech-to-text list APIs. Tag `grok-imagine-video*` as video, `grok-voice-transcribe*` as speech-to-text, and other `grok-voice*` as voice. Image-generation rows get capability `image` (or video, voice, or speech-to-text when the slug says so)
- In-process snapshot + TTL freshness. An unpinned `XaiClient` / `AsyncXaiClient` passes its API key into `list_models` and re-resolves chat (and unpinned image/video/voice defaults) when that cache expires (one hour). A pin on the client or the call stays fixed. `BOOTSTRAP_MODEL` is the empty-catalog fallback, not a live pin. Video and voice stay on the role default until a list row exists. Chat newest-sort is integer `(major, minor)`: `grok-5` above `grok-4.10` above `grok-4.7`. `grok-4.20` sorts as minor 2 so it stays older than `grok-4.3`. Every role ranks a stable id (no `-preview` segment) ahead of any `-preview` id before that version or created-date order. A preview is chosen only when that role has no stable candidate. Dashed (`YYYY-MM-DD`) and compact (`YYYYMMDD`) dates are snapshot markers in every role. A snapshot ranks behind the plain id or `-latest` alias of the same family. The date is not a version number. A trailing snapshot date on an undotted chat id (`grok-4-20260530`, `grok-4-2026-05-30`, and the same shapes on `grok-5`) is not that id's minor version, so it does not outrank the plain id or a higher dotted minor such as `grok-4.7`
- Opt-in disk persist: `list_models(..., persist_path=)` writes `{models: [...]}` after a successful SDK fetch (same shape `save_catalog_snapshot` writes). Writes go to a sibling temp file then `os.replace` so a failed write cannot truncate the last good snapshot. No default cwd/home path. Read order when no inject/test-fetch: fresh memory → SDK if key → persist file if present → `fixture_path` → bootstrap. Disk write errors are logged; the live list is still returned. `clear_catalog_cache` is memory-only (does not delete the file)
- Test inject: `inject_catalog`, `set_test_fetch`, `clear_catalog_cache`
- Capability tag `reasoning` comes from slugs that contain `reasoning` after stripping `non-reasoning` / `non_reasoning`
- General **chat** intents skip coding SKUs (`grok-build-*`, `grok-code-*`, `*code-fast*` **id**) unless the catalog is coding-only. Do not match aliases (`grok-4.5` currently aliases `grok-build-latest`). Coding-SKU skip does **not** apply to image/video/voice
- `cheapest`: lowest ranking price. **One price band** → same as `best` (newer is usually more efficient at the same list price). **Multiple bands** → oldest / non-reasoning in the cheapest band
- `best`: stable flagship in the role pool (`prefer_latest`), or the stable id that satisfies `need=`. A non-preview id beats any `-preview` id regardless of version or created date. Preview is chosen only when the role has no stable non-lite candidate. Every role ranks a non-lite id above any `-lite` segment first, then a stable id above `-preview`, so a newer lite id does not win `best` while a non-lite id exists. Lite can still win `economy` and `cheapest`. Lite wins `best` only when it is alone after `need=` filtering. `lite` is its own segment, so `latest`, `elite`, and `lites` are not lite. Dashed (`YYYY-MM-DD`) and compact (`YYYYMMDD`) dates are snapshot markers in every role. A snapshot ranks behind the plain id or the `-latest` alias of the same family and does not win `best` over it. The date is not a version number, including the minor of an undotted chat id such as `grok-4` or `grok-5`. When that family has only dated ids, the newest date wins. The penalty stays inside the family, so a newer dated-only family can still beat an older plain id
- **Feature map:** `feature_options(model=)` for settings knobs; `need=` on resolve so `best` is best **for the job**. 1.5 is the video flagship but cannot extend/edit. `need="video_extend"` picks quality. 1.5 Lite is the cheap text/image video SKU (`1080p` only). For `best` in every role, a stable id beats any `-preview` id, regardless of version or created date. A preview is `best` only when that role's candidates have no stable non-lite id. In every role, sort ranks every non-lite id above a `-lite` segment, then stable above `-preview` (ahead of version or created time). Extend, edit, and r2v extras go only to unversioned `grok-imagine-video`, its `-latest` alias, and a dated snapshot of that id (`grok-imagine-video-2026-05-30`). A versioned or unknown id such as `grok-imagine-video-2.0`, `grok-imagine-video-2.0-preview`, or `grok-imagine-video-3.0-lite` has empty extras until the catalog lists it, so `need=video_extend` does not pick it. A pin of an unknown id stays pinned. Today's watch ids, including the 1.5 family, classify as before. Video then uses the version with dashed (`YYYY-MM-DD`) and compact (`YYYYMMDD`) snapshot dates removed. Those dates are snapshot markers in every role, and the date is not a version number. The plain id or `-latest` alias ranks above a snapshot of the same family. When a family has only dated ids, the newest date wins. That penalty stays inside the family, so a newer dated-only family can still beat an older plain id. A created-date tie does not let a snapshot win on the id string. A newer `created` stamp, a higher version, or a date in the id (`-lite-2026-10-04`, `grok-imagine-video-1.5-2026-05-30`, `grok-imagine-video-2.0-preview`) cannot make lite or `-preview` into `best` over plain `grok-imagine-video-1.5` when a stable non-lite id exists. Chat extras (4.6+, flagship `grok-4.7`): web/X search, code execution, file attachments, collections search, image understanding, X video understanding, remote MCP. Newer SKUs may add tools; older may have fewer. Do not overload `ModelInfo.capabilities` (role tags).
- `economy`: newest model in the price band **strictly below** flagship; overlaps `cheapest` when a cheaper band exists, overlaps `best` when there is only one band. The same snapshot rule as `best` applies in that cheaper band, in every role: a dated id does not beat the plain id or `-latest` alias of its family. A lone `-lite` id in the band strictly below the flagship can still win `economy` and `cheapest`
- `resolve_model` / `resolve_model_selection(..., role="image"|"video"|"voice"|"speech-to-text")` use the same rules on that pool (default `role="chat"`)
- Speech-to-text ids (`grok-voice-transcribe-1.0`, `grok-voice-transcribe-2.0`, and any future `grok-voice-transcribe*`) are role `speech-to-text`, not `voice`. They resolve only on the speech-to-text path (`role="speech-to-text"`). Voice `best` and the default `voice_model` cannot be a transcribe id, including when the transcribe row has a newer `created` date
- Image, video, and voice ranking price: the public list rate wins over `input_per_million` when one exists. `input_per_million` is used only when no public list rate exists. Image proto `image_price` is mapped when present. Chat still ranks on `input_per_million`
- A list row may omit long and cached token rates. Usage metering copies each missing field the call needs from the shipped price table, looked up by the resolved catalog row id and then the request model string. A value set on the row wins. See [UsageObservability](UsageObservability.md) XK-AC-PRICE-1 and XK-AC-PRICE-2
- **Non-default host list (XK-AC-REGION-1, XK-AC-REGION-2).** The default host is `https://api.x.ai/v1` after one trailing slash is removed. That host does not call REST `GET /v1/models`, and resolve stays on the process-wide catalog. Any other host, scheme, or path fetches `GET <base>/models` once per client instance, with `Authorization: Bearer`, and caches that list for the client's lifetime with no TTL. Ids are `data[].id`. The kept row also stores `created` (Unix seconds; missing, non-integer, and ISO values stay unset) and `owned_by`. Payload price fields are ignored. Each id's role comes from the static catalog (shipped price-table ids, plus `grok-voice-transcribe-1.0` and `grok-voice-transcribe-2.0`). An id the static catalog does not know is chat only. The REST payload's role tag is ignored, because that list marks every model as chat. A known image id such as `grok-imagine-image` stays image. Best and economy for every role use only listed ids, with the same ranking rules as the default host. On a host that lists `grok-4.7` and `grok-4.6`, best chat is `grok-4.7`. A pin (client `model` / `image_model` / `video_model` / `voice_model`, or a per-call `model`) is sent unchanged, with no remap and no warning. When an unpinned role has no listed model, the call raises `RoleUnavailableOnHost` (a `XaiKitError` with `.role` and `.host`) before any request. Voice covers TTS and realtime (`role` `voice`). Speech-to-text covers REST STT and the STT websocket (`role` `speech-to-text`). There is no silent fallback to `api.x.ai`. If `GET /v1/models` fails (HTTP 500, connection refused, timeout, non-JSON, or HTTP 200 with an empty `data` list), the client logs one `WARNING` on logger `xaikit.catalog` naming the host, then uses the static catalog (injected rows, otherwise the bootstrap pair) and still sends the request to the configured host. The usage meter applies the documented 10% US endpoint token premium when the client host is `us.api.x.ai`. The premium covers input, cached input, output, and image input tokens. It is applied to the unrounded token cost and rounded once to 8 decimal places. Server `cost_in_usd_ticks`, when present, are kept unchanged. The default host, unknown hosts, and proxy hosts stay at the base price. Per-image, per-second, and per-minute fees are not marked up. See [UsageObservability](UsageObservability.md) `XK-AC-REGION-METER-1` and `XK-AC-REGION-METER-2`.
